# Ask broker discovery

Broker discovery and named-firm verification use separate routes. Discovery asks only for missing residence and instruments before searching. The clarification card is deterministic, invokes no model or research tools, and skips quota reservation on both web and mobile. Authentication and mobile AI consent still apply. Substantive answers retain normal Free/Pro usage checks.

Explicit country, instruments and the last six distinct requirement statements are saved in the existing session memory JSON. No database migration is needed. Follow-ups receive this memory; explicit changes override earlier preferences. IP location is not treated as confirmed residence.

Clarification is persisted before returning so immediate replies cannot race background history saving and accidentally consume quota. The candidate tool requires country and instruments. Broker categories filter out investment-only platforms for forex/gold requests before truncating candidates. Stored research dates, sources, legal entities and product categories accompany credibility scores. The card-submission tool refuses database shortlist names until individual verification has completed for them. Rejected submissions do not stop the model loop. The model compares at most two or three relevant options, checks current product and country eligibility where possible, and must identify unconfirmed eligibility and historical evidence. Stored scores are not endorsements or proof of suitability. Discovery comparisons retain up to 160 words, paragraph breaks and source URLs when displayed or reloaded, rather than losing later options to the ordinary three-sentence limit. Guru behaviour and TTS are unchanged.

Validation covers initial and partial clarification, named requests, preference retention and changes, no research/model calls during clarification, quota exhaustion on both API routes, and investment-only category exclusion.
