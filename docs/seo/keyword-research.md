Research date: 2026-07-08. Sources: Google SERPs + competitor analysis (BrokerChooser, WikiFX, Traders Union, Forex Peace Army, Myfxbook, Babypips, EarnForex, PropFirmMatch, Capital Companion, TrendSpider, FCA).

## How "keywords" actually work in 2026 (read first)

- **There is no `<meta name="keywords">` tag** — Google has ignored it since 2009 and stuffing it can look spammy. We did **not** add one.
- Keywords live in: **page titles, meta descriptions, H1/H2 headings, body copy, URL slugs, image alt text, and FAQ/schema** — and above all in **dedicated content pages**.
- **On-page metadata: done** (see the page map below).
- **The real traffic lever is content** — the informational articles + per-entity pages in the backlog. That's the content team's / SEO agency's job (Phase 4), not something metadata alone unlocks.

### The biggest play: programmatic per-entity pages
verify.trading already has a **verified-entity registry** (brokers, prop firms, gurus) with regulator citations. Generating a page per entity — *"Is [Broker] regulated? — verify.trading"* — targets the enormous long tail of `is [X] legit / [X] scam / [X] regulated` searches at scale. This is the highest-leverage organic opportunity, and it's a **code + content** project (a templated route reading the registry), not a metadata tweak. Flag for Phase 4+.

## Notes / guardrails
- Keep every keyword **truthful to the page** — no "unlimited," no fabricated features (we already fact-checked the existing copy).
- Prefer one clear primary keyword per page; don't target the same term on two pages (keyword cannibalisation).
- Titles ≤ ~60 chars, descriptions ≤ ~155 chars (the template appends `" | verify.trading"`).
